## 2026-08-24（会话 1：项目初始化与方案定稿）

### 背景与需求
- 目标：开发 Minecraft 1.20.1 mod，让 AI 控制玩家行为——**像一起玩的朋友**：既可自主生存，也可在聊天中接收指令；人设可配置更换。
- 前置：Keyboard mod（`D:\ClaudeCode\Minecraft_Bot_1.20.1`）已完整实现（v2 协议：18 动作 + 9 事件 + 12 错误码，实机验收全部通过），作为「合法接口的执行层」。

### 决策记录（D1–D6）
| 编号 | 决策 |
|---|---|
| D1 | AI 大脑 = **外部 Python 独立进程**，最终打包 exe 交付（用户为新手，双击即用；调试/改人设不重启游戏；不占游戏线程） |
| D2 | LLM = **DeepSeek**：`deepseek-v4-flash`（日常文本思考）+ `deepseek-v4-flash-vision-exp`（视觉；2026-08-21 上线，单图 ≤384 token，价格与 flash 一致——视觉方案可行且便宜） |
| D3 | **不修改前置 mod 及协议**（《最终协议.md》v2 为完整版）；感知/导航/视觉/背包扩展全部在 Tower mod 内完成 |
| D4 | Tower mod 内置 WS 客户端**转发**执行动作给前置 mod（24777）；对外新开 Tower 协议（端口 24778）——大脑只连 Tower |
| D5 | move_to 自动驾驶手动干预：**前进键 = 暂停**（松手继续）；**后退键 = 取消**导航 |
| D6 | 文档结构：`开发目录\` 下存放《开发指南.md》《开发日志.md》《功能列表.md》《项目总结.md》；项目根 `前置mod协议\` 存放前置协议副本 |

### 关键讨论结论
- 寻路用**游戏内原版寻路**（`PathFinder` + `WalkNodeEvaluator`，dummy 僵尸代理）——降低 LLM 负担、提高正确率，可行性确认；
- 视觉 = mod 截图存文件 → 大脑读图压缩 → base64 发 DeepSeek vision-exp；策略：按需 + 事件触发 + 低频周期，控成本；
- 方块感知用**结构化数据**（raycast + get_blocks + get_entities），视觉用于大局判断，两者互补；
- 感知/导航/视觉全部**游戏内实现**（需要世界访问），大脑只做决策——LLM 永远不思考"怎么走"，只思考"去哪"。

### 验收抓到的 bug（均修复后复验通过）
1. **`findPath` 第 5 参数 depth 语义误解**：depth 是「到达判定半径」（曼哈顿距离），非搜索深度——传 64 导致起点距目标 < 64 即"立即到达"，路径只剩起点。修复：depth=1
2. **waypoints 响应格式**：多包了一层 `{"waypoints": [...]}`，应为直接数组
3. **寻路未到达时 NPE 隐患**：A* 穷尽后 reconstructPath(bestNode=null) 会 NPE（高空目标 401 而非 304）。修复：越界预检 + 异常兜底
4. **测试脚本事件接收**：TowerClient.recv 递归缓存事件且每次递归重置超时，path_progress 事件流（1/s）导致 recv 永不返回、path_reached 永远"收不到"。修复：迭代式总超时 + wait_event 缓存轮询
