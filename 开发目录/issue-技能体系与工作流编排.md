# [提案] 技能体系重构：按大类分层 + 工作流编排

> 可直接复制为 GitHub Issue 正文。关联：`开发目录/功能列表.md`「生存知识技能」节。

## 背景与问题

当前大脑执行模式：LLM 每次排 `plan`（逐步骤），步骤引用技能/工具，`PlanExecutor` 顺序执行。

三个痛点：

1. **贵且易错**：复杂任务（如做熔炉 = 收集→合成→冶炼）LLM 要排 5-8 步 plan、多次调用，且每次推理配方/依赖容易出错（历史翻车：木棍双倍消耗、无工作台合木镐、全木板做工作台）。
2. **技能散、缺编排**：技能目前是平铺的原子级（砍树/做工作台/过水），缺少"大类能力"（挖矿、合成、战斗、交互）和它们之间的编排。
3. **LLM 负担重**：技能越多，注入 LLM 的技能清单越长，每步选择越难、越费 token。

## 提案：技能按大类分层 + 两层编排

### 核心思路

**宏观层（LLM）只管"大类阶段"**，**微观层（复合技能）代码确定性执行**，**原子层（工具/动作）跑腿**。

```
LLM 排 2-4 个大类阶段（如：获取材料 → 生产 → 交付）
        │
        ▼
复合技能内部 = 确定性流水线（检查→分支→执行→验证，可调其他复合技能）
        │
        ▼
原子工具/动作（move_to / attack / search_find / get_state ...）
```

- LLM 不再编排每一步，只选"哪个大类技能 + 目标"
- 每个复合技能内部是代码流水线，细节由代码保证
- 复合技能可互相调用（挖矿供料给合成、合成供镐给挖矿）

### 技能体系（按大类 + 细分）

```
brain/skills/
  kc.py                    # 知识数据表（矿物/工具/配方/生物）——所有技能共享
  mine_ore.py              # 挖矿类：知识表(Y层/掉落/镐等级)→检查工具→(缺则合成)→搜索→挖→验证
  craft_chain.py           # 合成类：配方依赖链→检查背包→缺材料(mine_ore)→精确合成→验证
  battle.py                # 战斗类：索敌→接近→攻击→低血撤退
  interact/
    container.py           #   容器交互：打开→取/放→关闭
    place.py               #   放置方块（铺路/建造）
    farm.py                #   种植：耕地→播种→等待→收获
    pickup.py              #   拾取掉落物
```

### 工作流编排机制

**1. 复合技能 = 流水线**（复用现有 `ctx.run_skill` 组合 + `search_find` 搜索）

```python
class MineOreSkill(Skill):
    name = "mine_ore"
    description = "挖指定矿物：自动检查/合成镐子，按 Y 层搜索并挖掘"
    def run(self, ctx, args):
        ore = args["ore"]                       # LLM 只给目标
        info = KC.ore(ore)                      # ① 知识表：Y层/掉落/镐等级
        if not has_pick(ctx, info.level):       # ② 前置检查
            ctx.run_skill("craft_chain", {"target": info.pick})   # ③ 缺→自动合成
        pos = search_ore(ctx, ore, info.y)      # ④ 按 Y 层搜索
        mine(ctx, pos); verify_drop(ctx, ore)   # ⑤ 挖 + ⑥ 验证掉落
        return "完成..."
```

**2. 前置依赖声明（可选增强）**

技能声明 `requires`，执行器自动补齐前置，编排对 LLM 更透明：

```python
class MineOreSkill(Skill):
    requires = [("has_pick", "iron")]   # 没有对应镐 → 自动插入合成步骤
```

**3. plan 工具简化**

LLM 只见大类技能清单（挖矿/合成/战斗/种植/容器…），输出 `{goal, steps: [大类技能调用×2-4], accept}`，子步骤由复合技能内部流水线消化。

## 收益

- **省 token**：LLM 从 5-8 步 plan 降到 2-4 个大类调用；一次技能调用替代多次 LLM 规划
- **不易出错**：配方/数量/工具依赖由代码保证，不靠 LLM 推理
- **技能解耦可复用**：大类技能互相调用闭环，新增能力只加一个技能文件
- **可扩展**：知识表加一行 = 新配方/矿物，不改逻辑

## 落地计划

1. **`kc.py` 知识数据表**：矿物（Y 层/掉落/镐等级）、工具进度链（木→石→铁→钻石）、基础配方表——先覆盖挖矿 + 基础合成
2. **`mine_ore.py` + `craft_chain.py`** 两个复合技能（流水线样板）
3. 实机验证（挖圆石/铁矿 → 合成石镐/铁镐/熔炉）
4. 按同样模式扩展交互（容器/种植/放置）、战斗大类
