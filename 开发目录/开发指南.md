# Tower 开发指南

> 项目：Tower（AI 智能体 mod，名称待定）——让 AI 像朋友一样操控 Minecraft 玩家。
> 配套文档：`开发目录\功能列表.md`（功能与里程碑）、`开发目录\开发日志.md`（变更记录）、`开发目录\项目总结.md`（总览）、`Tower协议.md`（协议 v1）。

---

## 1. 项目简介

在 Minecraft 1.20.1（NeoForge 47.x，客户端）中实现「AI 操控玩家」的完整方案：

- **自主生存**：AI 自己决策——采集、合成、建造、战斗、进食、睡眠；
- **聊天互动**：AI 能听到玩家说话并回应，也可主动开口；
- **人设可换**：通过配置文件随时改变 AI 的性格与行为准则。

## 2. 总体架构（三层 + 护栏）

```
┌─────────────────────────────────────────────┐
│ 决策层：AI 大脑（外部 Python 进程，打包 exe）       │
│   DeepSeek 模型（文本 flash + 视觉 vision-exp）  │
│   人设/目标/记忆配置（记事本可改，热重载）           │
└───────────────────▲──────────────────────────┘
                    │ WebSocket（Tower 协议 v1，端口 24778）
┌───────────────────▼──────────────────────────┐
│ 感知/导航层：Tower mod（游戏内，本项目）           │
│   寻路 move_to / 方块感知 / 实体感知 / 截图 / 背包  │
│   ↓ 转发（WS 客户端连接 24777）                  │
│   前置 Keyboard mod（执行层，v2 协议，不改动）      │
└───────────────────▲──────────────────────────┘
                    │ 合法玩家输入
┌───────────────────▼──────────────────────────┐
│ Minecraft 1.20.1 游戏本身                       │
└─────────────────────────────────────────────┘
```

**关键原则：**
- **前置 mod 是完整版**：v2 协议（18 动作 + 9 事件 + 12 错误码）**原封不动**，作为「手和脚」的执行层；
- **新功能全部在本 mod 内完成**：感知（方块/实体/射线）、导航（寻路）、视觉（截图）、背包扩展，以及对外协议（Tower v1）；
- **大脑在游戏外**：决策不占用游戏线程；改人设、改提示词不用重启游戏；
- **硬编码安全护栏**（不经过 LLM）：低血量自动撤退/进食、岩浆紧急脱困、AI 失联自动归零输入。

## 5. 工作规范（必须遵守）

1. **文档优先**：任何方案/协议变更先改对应文档，再动代码。
2. **按步推进**：严格按《功能列表.md》里程碑顺序执行，一次只做一个步骤，验收通过再进下一步；不跳步、不夹带未规划功能。
3. **验收驱动**：每步有明确验收标准，完成后如实报告结果；失败必须报告原因，不得虚构或掩盖。
4. **日志同步**：每次改动（完成步骤/变更决策/修复问题）后追加《开发日志.md》。
5. **不生成未获准代码**：用户明确指令后才写代码；讨论阶段只产出文档。
6. **前置 mod 红线**：不得改动前置 mod 源码与协议；其能力以《前置mod协议\最终协议.md》为准。
7. **线程纪律**：游戏对象访问必须在游戏主线程；网络线程只做收发。
8. **交流语言**：与用户交流使用中文。
